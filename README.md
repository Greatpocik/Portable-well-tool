# Portable Well Tool для ИС «ОДС»

##  О проекте

**Portable Well Tool** — это портативное десктопное приложение, разработанное для консолидации данных из корпоративной ИС и автоматизации рутинных операций.

Проект был создан в рамках **Региональной научно-технической конференции молодых специалистов НК «Роснефть» (2025)** и представлял собой инициативную разработку по решению бизнес-проблем отдела сопровождения.

> ** Статус проекта:** Pet-Project / PoC. Не был внедрён в промышленную эксплуатацию (см. раздел «Почему проект не был реализован»). Является полностью рабочим прототипом, демонстрирующим архитектурный подход, работу с БД и навыки проектирования десктопных приложений.

## Проблематика

Текущий рабочий инструмент сотрудников — приложения **ЦДС-Менеджер** и **ЦДС-Пульт** — создаёт три ключевых ограничения для эффективной работы:

1. **Длительное развёртывание.** Для подготовки нового рабочего места требуется установить и настроить клиент Oracle и сами приложения. Процедура требует временных затрат и участия специалиста поддержки.
2. **Раздробленность данных.** Для полного анализа данных по скважине пользователю необходимо переключаться между разными модулями ЦДС: реестром ТКРС, Сетевым графиком и ЦДС-Пульт.
3. **Низкая скорость обработки.** Проверка группы скважин невозможна — все операции выполняются только для одной скважины за раз.

---

## Как приложение решает эти проблемы

| Проблема | Решение в приложении |
|---|---|
| Длительное развёртывание | **Portable EXE** — автономный исполняемый файл. Запуск без установки клиента Oracle и прав администратора. |
| Раздробленность данных | **Консолидированный просмотр** — сводные данные по скважинам из разных модулей в едином интерфейсе. |
| Низкая скорость обработки | **Автоматизация групповых операций** — анализ данных не для единичных скважин, а для произвольно сформированных групп. |
| Отсутствие групповых операций | **Формирование групп скважин** и пакетная работа с ними. |

## 🔐 Безопасность и ролевая модель

Безопасность в приложении построена на связке **Windows-аутентификации** и **«белого списка»** пользователей.

### Алгоритм авторизации

1. Приложение использует встроенные средства .NET для получения контекста текущего пользователя — его **домена и логина**.
2. Полученные данные сверяются со **списком пользователей приложения** в базе данных.
3. Если пользователь найден — приложение **загружает его права** из соответствующей таблицы и отображает интерфейс.
4. Если пользователя в списке нет — вызывается **системный запрос учётных данных Windows (WinAuth)**.

<img width="1213" height="514" alt="image" src="https://github.com/user-attachments/assets/4aba8bf1-7f44-4525-99f6-fb77afdd328f" />


**Преимущество:** приложение не работает с паролями и не хранит их. Аутентификация выполняется исключительно средствами ОС.

### Ролевая модель доступа

После успешной авторизации и перед отображением интерфейса приложение определяет, какими правами обладает пользователь, и делает доступными соответствующие кнопки и элементы управления.

**Как это работает:**

- Для обычного пользователя часть функционала **скрыта или недоступна** — например, некоторые контекстные меню и операции с группами скважин.
- Для администратора **весь функционал доступен сразу** — без дополнительных настроек.
- Права хранятся в базе данных и загружаются при авторизации, что позволяет управлять доступом без пересборки приложения.

## Сценарий использования: Автоматическая проверка скважин на возможность удаления

Один из регулярных рабочих процессов отдела — проверка скважин на готовность к удалению из системы по запросу отдела СУБД.

Существующий сценарий (от 1 часа до нескольких дней)

1. Специалист сопровождения получает письмо со списком скважин.
2. Вручную проверяет наличие данных в таблицах Реестра ТКРС, ЦДС-Пульта и Сетевого графика.
3. Для каждой скважины из списка операция повторяется отдельно.
4. После завершения проверки специалист формирует и отправляет ответное письмо с результатом.

Новый сценарий с использованием приложения (от 5 до 30 минут)

1. Сотрудник сектора баз данных формирует группу скважин в интерфейсе приложения.
2. Запускает проверку — приложение автоматически собирает информацию из необходимых объектов базы данных.
3. Через несколько минут на экране формируется готовая таблица с результатами.
4. Таблицу можно скопировать и отправить ответным письмом.

## Сценарий использования: Поиск данных по скважине

Существующий процесс
Для получения информации по скважине пользователю необходимо постоянно переключаться между модулями приложений ЦДС и повторять одни и те же операции:

1. Открыть реестр ТКРС
2. Перейти в ЦДС-Пульт
3. Проверить Сетевой график
4. Ручную собрать данные воедино

Новый процесс с использованием приложения

1. Пользователь находит скважины по заданным условиям через интерфейс приложения. Поддерживаются регулярные выражения, что повышает удобство поиска.
2. После нахождения нужных скважин можно выбрать одну или несколько и отобразить данные по ним в виде сводной таблицы — без переключения между модулями.
3. Данные консолидируются из разных источников: журнал событий, события из пульта, история постановки бригады ТКРС, суточное нахождение ТКРС, планы ГТМ.

## 🚧 Почему проект не был реализован

Проект создавался как Proof of Concept в рамках конференции. После защиты прототипа он не получил дальнейшего развития: на тот момент я переключился на другие рабочие задачи, а проект не был включён в официальный план разработки. 

---

## ⚠️ Известные ограничения и планы по улучшению

Проект создавался в сжатые сроки, поэтому часть решений была упрощена. В текущей работе я бы применил более зрелые подходы:

| Ограничение | Как было в PoC | Как сделал бы сейчас |
|---|---|---|
| **Тестирование** | Юнит-тесты отсутствуют | Покрыл бы ключевую логику (сервисы, ViewModel) тестами на xUnit |
| **Логирование** | Минимальное | Добавил бы структурированное логирование |
| **Конфигурация** | Строка подключения в коде | Вынес бы в конфиг-файл с поддержкой переменных окружения |
